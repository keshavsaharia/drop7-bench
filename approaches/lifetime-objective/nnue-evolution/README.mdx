The search that plays Drop7 looks a few moves ahead and then asks a hand-written
formula how promising each board it can reach looks. This experiment replaces
that formula, for the three-move search, with a small neural network. The
network is first taught to imitate a slower search that looks five moves ahead,
and then improved by evolution on the only thing the program is paid for: the
final score of complete games.

## The idea in one picture

Every search in this repository has the same shape: imagine each legal column,
imagine the next disc, imagine the reply, and so on for a few moves, then stop
and ask a [leaf evaluator](/learn/glossary) how good the board at the end of
each imagined line is. The points won along the way are known exactly; the leaf
guesses the rest. The frozen fair leaf is a sum of eighteen hand-written terms.
On the positions the teacher has recorded so far, that guess carries roughly
nineteen twentieths of the difference between one column and another, so the
leaf is where the decision is made.

<NnueSketch caption="The NNUE reads exactly what a player can see, turns it into 135 active features out of 8,902 possible ones, sums the matching rows of a weight table, passes the sum through two small layers, and returns one number in units of a row rise (17,000 points). Evolution changes the weights only." />

An [NNUE](/learn/glossary) is a network built for exactly this job: it is
sparse enough to evaluate in a microsecond, which is what a leaf that is called
hundreds of thousands of times per decision can afford, and it is expressive
enough to encode board patterns that eighteen linear terms cannot. The one on
this page has about 572,000 weights, almost all of them in the first table.

## Why evolve, when you could just imitate?

Two earlier lines of work in this program each failed in an instructive way.
Networks trained to imitate a search learned the positions the teacher visited
and then could not rank the six sibling moves it never played (the
[sibling trap](/learn/concepts/ranking-siblings)). And the one time a leaf was
tuned by evolution on whole-game score directly, the eighteen hand-written
weights of the fair leaf under CMA-ES, the optimiser followed selection noise
into a worse evaluator
([the first leaf evolution](/approaches/lifetime-objective/leaf-evolution)).
Its post-mortem was precise: with 32 games per candidate and a paired standard
deviation near 200,000 points, fresh seeds every generation left selection
noise alone to steer.

This design keeps what each failure taught. Imitation is used only as a warm
start, from a corpus that records the teacher's value for every legal column at
every position, so the sibling-coverage hole is closed at the source. Evolution
then refines the warm start on the deployed objective, but with the noise
handled: every candidate in a generation plays the same games.

<PairedSeedsSketch caption="Common random numbers. Because every candidate and both controls play exactly the same seeds in a generation, the difference between two candidates' mean scores is a difference in evaluators, not in the discs they were dealt. Selection then compares ranks, so one lucky game moves a candidate up a few places rather than dragging the whole generation." />

## How it works, stage by stage

<EvolutionPipeline caption="Four stages. The teacher, the corpus, the warm start, the evolution and the elite re-selection all read seeds from the training lease, which may be read again. The screen reads a separate block of seeds that nothing has ever opened, exactly once, after the candidate's weights are frozen and hashed." />

### Stage A: a teacher that can see a whole rise

The frozen fair evaluator, driven by the
[fast Rust bitboard engine](/approaches/fair-expectimax/rust-engine), plays
training games at depth 5 with seven chance strata. Five moves is one full
row-rise cycle, so every rise consequence of a root move is inside the teacher's
horizon: the slow risks a three-move search cannot see, such as a high number
that can no longer be cracked open or a 1 parked beside a gray disc, are visible
to it. At every position the teacher faced, the corpus records the board, the
next disc, the moves until the rise, and the teacher's value for all seven
columns. The search computes those seven values anyway, so the corpus is
sibling-complete for free. Each teacher game is capped at 500 moves, and the
stage stops starting new games after a fixed wall-clock budget; whatever whole
games have completed are the corpus.

### Stage B: imitation as a warm start

The NNUE is fitted to the teacher's values with the Adam optimiser on a Huber
loss measured in rise units, with a whole-origin split: a game and all of its
positions are always on the same side of the split, so validation never sees a
position from a game it trained on. Training runs for 16 epochs and the epoch
with the lowest validation loss is frozen as the warm start. A deployment-
faithful probe then puts that network inside the real depth-3 search on
held-out positions and asks how often the search now picks the teacher's
column. This stage only has to land in a good region; the repository's own
evidence says a supervised student alone does not hold the teacher's ordering,
and the theory says so too.

### Stage C: evolution inside the deployed search

<GenerationLoop caption="One generation. Thirty-two candidates play the same fresh block of thirty-two seeds as the leaf of the real depth-3 search; the four fittest are copied unchanged; the other twenty-eight slots are filled by tournaments of three whose winner is copied and mutated. The frozen fair leaf and the unevolved warm start play every block as controls and are never selected." />

**Generation 0.** Candidate 0 is the warm start exactly as stage B left it.
Candidates 1 to 31 are copies with Gaussian noise added to every weight, twice
as wide as the noise used later, so the first generation spans a small
neighbourhood instead of thirty-two identical clones.

**One generation, in order.**

1. *Draw a fresh block of seeds.* Generation `g` plays the 32 seeds starting at
   `0xa52e0500 + 32·g`. No block is ever reused, so a candidate cannot score
   well by memorising particular games.
2. *Everyone plays the same games.* Each candidate plays all 32 seeds as the
   leaf of the depth-3, seven-stratum fair search with the ordinary 2,000-move
   cap. The frozen fair leaf and the unevolved warm start play the same seeds
   as two control rows. That is 34 × 32 = 1,088 complete games per generation,
   one game per thread across the machine; a game's result does not depend on
   which thread played it.
3. *Fitness is the mean score.* Nothing is fitted, weighted or smoothed: a
   candidate's fitness is the arithmetic mean of its 32 final scores. Because
   every candidate saw the same games, the only noise that matters when
   comparing two of them is the paired difference, not the game-to-game
   spread.
4. *Keep the best four unchanged.* The four fittest candidates are copied into
   the next generation as they are, so the population can never lose its best
   evaluator to a bad mutation.
5. *Fill the other 28 slots by tournament and mutation.* For each open slot,
   three candidates are drawn at random and the fittest wins. A copy of the
   winner is made, and every weight in the copy is perturbed by Gaussian noise
   whose standard deviation is 5% of the standard deviation of the tensor it
   belongs to, with a small floor so an all-zero tensor can still move.
6. *Checkpoint, then mark complete.* The next population is written to disk
   before the generation's artifact (every game of every candidate and control,
   one row per game) and its summary line. A crash between the two replays the
   generation from identical inputs and produces identical output; a crash
   after them resumes at the next generation. A `STOP` file or the wall budget
   ends the loop at a generation boundary.

**After the last generation.** The eight fittest candidates of the final
generation each replay a fresh 128-game block, and the one with the highest
mean is frozen as the candidate. Its SHA-256 is recorded before the screen
block is opened, so the vector that is screened is provably the one that was
selected. This step exists because the last generation's leader is partly a
lucky draw: the best of thirty-two noisy estimates is biased upward, and 128
fresh games shrink that bias before anything is claimed.

**What the controls are for.** The fair leaf's row answers, generation by
generation, "is the population better than the evaluator it replaced, on
exactly these games?" The theory's training-signal falsifier reads that row.
The warm start's row answers "did evolution move anything?": if the population
never separates from the unevolved network on the same games, mutation is a
random walk around the starting point.

### Stage D: one look at never-read games

The frozen candidate plays 64 games on a seed block nothing has ever opened,
against three other arms on the identical seeds: the same depth-3 search with
the frozen fair leaf (the comparator), the same search with the unevolved warm
start (the ablation, isolating what evolution added), and the fair leaf at
depth 4 (the program's standing reference, diagnostic only). The screen is
played exactly once, whatever it shows.

## How much can a leaf change a decision?

A fair question about this whole design is whether a leaf evaluator can move a
decision at all once a five-move search has banked the cascade points along
each line. The run answered it with a retained diagnostic before evolution
started: on a frozen snapshot of thirty teacher games, every root was searched
twice at each depth, once with the fair leaf and once with a leaf that returns
zero, so the only difference between the two sets of column values is the leaf
term. The numbers below are copied from those artifacts.

At every depth the leaf term carries about nineteen twentieths of the spread
between columns, and removing it changes the chosen column at roughly half of
the roots. The search does not dilute the leaf; it multiplies it, because the
same evaluator is applied at every frontier position of every line. That is
why a better leaf is worth pursuing and why a worse one is dangerous.

## What would count as success, and what a clean rejection looks like

The gate was fixed before any leased seed was read. On the 64 held-out games,
the evolved candidate must beat the frozen fair leaf at the identical depth-3
configuration with a paired mean difference whose one-sided 95% bootstrap lower
bound and Student-t lower bound are both above zero, the difference must be
positive in both halves of the block, and the candidate's lower-quartile score
may not fall below the fair leaf's. Every generation artifact and the screen
artifact must record zero illegal and zero incomplete decisions, and the
screened weights must hash to the value recorded before the screen lease opened.

If the candidate passes but the unevolved warm start passes equally on the same
seeds, the evolutionary stage contributed nothing and the theory's second leg
is refuted even though the network stands. If the candidate fails, the result
rejects this exact configuration: this model class, this teacher depth, this
optimiser and budget, this deployment depth. It does not reject the idea of a
learned leaf, and the retained corpus, warm start and populations remain
available for a successor experiment with its own record and leases.

## What this taught us, and what is still open

- **Whole-game evolution with common random numbers moves a 572,000-weight
  leaf.** That is the finding the first, CMA-ES leaf evolution could not
  produce. The population separated from its warm start steadily across all
  sixty generations, the ten-generation paired margins rising from about
  +5,000 to about +40,000 for the mean and to +77,000 for the best candidate,
  and the held-out ablation confirmed it out of sample at +35,375 with a lower
  bound well above zero. The curve had not flattened at generation 60.
- **Imitation of state values is the weak link.** The warm start fitted the
  teacher's numbers closely (validation Pearson 0.95) yet, placed inside the
  real depth-3 search, it picked the teacher's column only 44% of the time,
  about what a leaf that returns zero manages, and it played at half the fair
  leaf's level. Evolution then had roughly 150,000 paired points to make up
  and made up a quarter of them.
- **The teacher is the expensive part.** A depth-5, seven-stratum search cost
  about 78 seconds per position at full parallelism, four to seven times the
  pilot's projection, so the corpus closed at 177 games instead of 512. Whether
  a larger corpus would have produced a warm start that holds the ordering is
  untested.
- **The leaf decides.** The leaf-swing diagnostic above turned a design
  assumption into a measured fact before any training signal was read, and the
  screen agrees: swapping the leaf moved the mean by more than 100,000 points
  in both directions.
- **Open.** Where the still-rising curve plateaus (a continuation from the
  generation-60 population on a fresh lease would tell), whether a warm start
  trained on ordering rather than value closes the gap, and whether a larger
  teacher corpus changes either answer. Each is a new experiment with its own
  record and leases; the retained corpus, warm start and populations are the
  starting material.

## The implementation

A std-only Rust crate (`approaches/lifetime-objective/nnue-evolution/`) with a
path dependency on the proven engine; the reference crate is not modified. Five
binaries: `gate` (the CHECK-tier mechanics suite), `teacher_corpus` (stage A),
`pretrain` (stage B), `evolve` (stage C, checkpointed and resumable, with
`--select` for the elite re-selection), and `screen` (stage D, emitting the
population-artifact format the repository's existing `compare.py` consumes
unchanged). The NNUE reads exactly the public state, and the
information-boundary gate proves that states differing only in score, level or
move count produce bit-identical evaluations.

The stages are driven by `scripts/pipeline.sh` (`RUN_ID=… THREADS=32
scripts/pipeline.sh corpus|pretrain|evolve|select|screen|compare|chain`), which
wraps every stage in `scripts/with-rusage.py` so wall, CPU and peak memory land
in `rusage.jsonl`, opens the screen lease through `scripts/open-screen-lease.py`
only when the candidate hash file exists, and refuses to run the screen twice.
`scripts/analyze.py --run <run>` summarises whatever artifacts exist into
`analysis.json` and `analysis.md`.

**How to continue from here.** Every generation's population is on disk, so a
later experiment can resume the loop from any `population-NNN.bin`, start a new
run from `candidate-weights.bin`, or change one operator at a time. Doing so is
a new experiment: it needs its own record, its own training lease (the fitness
blocks above are spent), and a fresh never-read screen block.
