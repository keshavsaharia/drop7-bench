The search that plays Drop7 best looks four moves ahead and then asks a
hand-written function how promising the resulting board is. That function — the
[leaf evaluator](/learn/glossary) — is where every learned-policy experiment in
this program has gone to fail, and it failed in two distinct ways. Models
trained to imitate a search learn the states the teacher visited and then cannot
rank the six sibling moves it did not play (the
[sibling trap](/learn/concepts/ranking-siblings)). And the one time the leaf was
tuned by evolution on whole-game score directly, the optimiser followed
selection noise into a worse evaluator
([the CMA-ES leaf evolution](/approaches/lifetime-objective/leaf-evolution)).

This approach keeps what each failure taught and changes the rest.

## The design in three stages

**Stage A — a teacher that can see a whole rise.** The frozen fair evaluator,
driven by the [fast Rust bitboard engine](/approaches/fair-expectimax/rust-engine),
plays training games at depth 5 with seven chance strata. Five moves is exactly
one row-rise cycle, so every rise consequence of the root move is inside the
teacher's horizon — the slow risks a depth-3 search cannot see (a high number
that can no longer be cracked open, a 1 parked next to a gray disc) are visible
to it. Every root is recorded with the teacher's value for **all seven columns**,
which the search computes anyway: the corpus is sibling-complete by construction,
so the coverage failure that sank earlier students is removed at the source.

**Stage B — supervised warm start.** A compact NNUE-style network (the
leaf-affordable class this repository has already characterised: 8,902 sparse
features of which 135 are active per state, about 572k parameters, microsecond
inference) is fitted to the teacher's state values with a whole-origin split —
a game and all its roots are always on the same side of the split. This stage
only needs to be a good starting region; the repository's evidence says a
supervised student alone will not hold the teacher's ordering, and the
preregistration says so too.

**Stage C — evolution on the deployed objective.** The warm-started weights are
then refined by a mutation-only genetic algorithm whose fitness is the thing
the policy is actually paid for: the mean score of complete games, played by
the exact deployed configuration (depth 3, seven strata, the candidate NNUE as
its leaf). Every candidate in a generation plays the **same fresh block of
seeds** (common random numbers), and the frozen fair leaf plus the unevolved
init play every block as paired controls.

## Why this might work where the first evolution failed

The 18-weight CMA-ES run failed its held-out screen at −30,300 points, and the
post-mortem was precise: fresh seeds per generation removed overfitting as
designed, "and left selection noise alone to steer, which at 32 games per
candidate and a paired sd near 200,000 is a random walk." This design answers
that diagnosis directly:

- **Paired blocks.** Every candidate in a generation plays identical seeds, so
  selection compares paired differences rather than independent noisy means.
- **An ordinal selection rule.** Tournament selection moves ranks, not
  magnitudes, so one lucky million-point game cannot drag a generation.
- **A warm start in weight space.** Mutation refines a functioning evaluator
  instead of searching raw leaf constants; the per-tensor step size scales with
  each tensor's own spread.
- **Cheap deployment depth.** Depth 3 costs roughly a fiftieth of the depth-4
  search the first evolution tuned, so the same machine budget buys an order of
  magnitude more fitness games per generation.
- **A noisy-champion guard.** The candidate is not the last generation's lucky
  leader: the top eight elites are re-evaluated on a fresh 128-game block and
  only the winner is frozen for the screen.

Gradient-free training of networks this size and far larger is established
(Such et al., *Deep Neuroevolution*, 2017; Salimans et al., *Evolution
Strategies as a Scalable Alternative to RL*, 2017, whose common-random-number
trick this design borrows), and evolving position evaluators is established in
the sister stochastic game 2048 (Jaśkowski's coevolutionary CMA-ES line of
work). The open question is not feasibility; it is whether whole-game evolution
moves a leaf that distillation alone cannot.

## What would count as success — or a clean rejection

The frozen candidate is screened **once** on 64 never-read paired development
games against the identical depth-3 search with the frozen fair leaf: the gate
is a positive paired delta with both bootstrap and Student-t 95% lower bounds
above zero, positive in both halves, and no lower-quartile regression. The
unevolved init plays the same seeds as an ablation — if the init passes equally,
the evolutionary stage contributed nothing and the theory's second leg is
refuted even if the candidate stands. The fair leaf at depth 4 plays the same
seeds as the program's standing reference. Everything is frozen in the
[experiment record](/research) before the screen lease opens, and the seed
leases (`0xa52e0300` training, `0xa52e1300` screen) are recorded in the
repository's seed registry.

## How the evolutionary training runs, step by step

This section is for a reader who wants to follow the loop without reading
`evolve.rs`. Everything below is what the binary actually does; the constants
are the frozen protocol's.

**What is being evolved.** The NNUE is a table of about 572,000 numbers. Given
a public board, the next disc, and the moves left until the next row rise, it
adds up 135 rows of that table (one per active feature), passes the sum through
two small dense layers, and returns one number: how good the position is, in
units of one row-rise bonus (17,000 points). The depth-3 search calls it at
every leaf. Evolution never changes the search, the features, or the network's
shape — only the 572,000 numbers.

**Generation 0.** Candidate 0 is the distilled network exactly as the
supervised stage left it. Candidates 1 to 31 are copies of it with Gaussian
noise added to every weight, twice as wide as the noise used later, so the
first generation already spans a small neighbourhood instead of 32 identical
clones.

**One generation, in order.**

1. *Draw a fresh block of seeds.* Generation `g` plays the 32 seeds starting at
   `0xa52e0500 + 32·g`. No block is ever reused, so a candidate cannot score
   well by memorising particular games.
2. *Everyone plays the same games.* Each of the 32 candidates plays all 32
   seeds as the leaf of the depth-3, seven-stratum fair search, with the
   ordinary 2,000-move cap. The frozen fair leaf and the unevolved
   supervised-init network play the same 32 seeds as two control rows. That is
   34 × 32 = 1,088 complete games per generation, spread over the machine's
   cores one game per thread; the result of a game does not depend on which
   thread played it.
3. *Fitness is the mean score.* Nothing is fitted, weighted, or smoothed: a
   candidate's fitness is the arithmetic mean of its 32 final scores. Because
   every candidate saw the same 32 games, the only noise that matters when
   comparing two candidates is the paired difference between them, not the
   full game-to-game spread.
4. *Keep the best four unchanged.* The four candidates with the highest fitness
   are copied into the next generation exactly as they are (elitism), so the
   population can never lose its best evaluator to a bad mutation.
5. *Fill the other 28 slots by tournament and mutation.* For each open slot,
   three candidates are drawn at random; the one with the highest fitness
   wins. A copy of the winner is made, and every weight in the copy is
   perturbed by Gaussian noise whose standard deviation is 5% of the standard
   deviation of the tensor it belongs to (with a small floor so an all-zero
   tensor can still move). Tournaments compare ranks, not magnitudes, so one
   lucky million-point game moves a candidate up a few places rather than
   dragging the whole generation toward it.
6. *Checkpoint, then mark complete.* The new population is written to
   `population-{g+1}.bin` before `gen-{g}.json` (every game of every candidate
   and control, one row per game) and the `progress.jsonl` summary line are
   written. A crash between the two replays generation `g` from identical
   inputs and produces identical output; a crash after them resumes at `g+1`.
   The `STOP` file and the wall budget end the loop at a generation boundary.

**After the last generation.** The eight fittest candidates of the final
generation each replay a fresh 128-game block (`0xa52e0c80`), and the one with
the highest mean is frozen as `candidate-weights.bin`. Its SHA-256 is recorded
before the held-out screen block is opened, so the vector that is screened is
provably the one that was selected. This step exists because the last
generation's leader is partly a lucky draw: the best of 32 noisy estimates is
biased upward, and 128 fresh games shrink that bias before anything is
claimed.

**What the controls are for.** The fair leaf's row answers "is the population
better than the evaluator it replaced, on exactly these games?" generation by
generation; the theory's own training-signal falsifier reads it. The init's
row answers "did evolution move anything?": if the population never separates
from the init on the same games, mutation is a random walk around the warm
start.

**How to continue from here.** Every generation's population is on disk, so a
later experiment can resume the loop from any `population-NNN.bin`, start a
new run from `candidate-weights.bin`, or change one operator at a time. Doing
so is a new experiment: it needs its own record, its own training lease
(the fitness blocks above are spent), and a fresh never-read screen block.

## The implementation

A std-only Rust crate (`approaches/lifetime-objective/nnue-evolution/`) with a
path dependency on the proven engine — the reference crate is not modified.
Five binaries: `gate` (the CHECK-tier mechanics suite), `teacher_corpus`
(stage A), `pretrain` (stage B), `evolve` (stage C, checkpointed and
resumable), and `screen` (stage D, emitting the population-artifact format the
repository's existing `compare.py` consumes unchanged). The NNUE reads exactly
the public state — visible board, visible next disc, moves until the rise — and
the information-boundary gate proves that states differing only in score,
level, or move count produce bit-identical evaluations.
